# Meow 分阶段重构计划

状态：**计划基线；P0 文档梳理完成，P1–P8 尚未实施。** 日期：2026-10-23。

架构、功能与数据来源见 [architecture.md](architecture.md)。本轮只形成文档，不改应用代码、配置、数据库或部署，不把静态审计当作运行验收。

## 1. 已确定的范围与实施原则

用户已确认：以当前 `server/`（Express + SQLite）为基础重构为唯一业务后端；删除 Cloudflare Pages / Workers / D1 等其他后端支持；**同时退役 Electron 打包及桌面专属代码**。目标交付只有本地正常开发/运行与 Docker。浏览器中的笔记、画布、回顾、音乐、AI、分享等功能保留。

本计划推荐继续使用 Node/Express/SQLite，逐步引入严格 TypeScript、统一契约、模块化单体、后端权威数据与可恢复的离线待提交队列；附件首版默认由自有后端文件卷管理。S3/R2 历史对象需迁移或明确保留为可读外部引用；不把它们误删，也不为目标首版新增多存储平台选择器。AI/音乐等第三方能力作为受控集成保留，密钥与有权限要求的请求收口后端。

实施按用户后续授权的阶段进行。每阶段先验证上一阶段入口条件，再提交可回退的小批次；不得跨越数据迁移门禁提前删除旧代码。现有源码中的安全或同步缺陷不作为必须保留的行为。

## 3. 各阶段执行清单

### P1：工程基线与可恢复样本

**范围**：`package.json`、锁文件/忽略规则、Node 配置、lint/TypeScript/test 配置、质量 CI、测试夹具；必要时小步分离 `server/index.js` 的创建应用与监听入口，使导入测试不创建真实数据库或启动端口。先建立 lint 基线再逐项收敛，不以关闭规则/大面积 ignore 隐藏问题。

- 合成样本覆盖：普通与仅置顶笔记、ID 数组/对象数组两版置顶、公开/私有、反链、录音、旧时间别名、画布、曲库、回顾、设置、删除墓碑、损坏 JSON、空库、缺字段旧库、含 `user_id` 的旧 D1 导出。
- 建立当前行为特征测试；已知缺陷以明确失败/待修条目记录，不把不安全行为断言成正确行为。
- 定义全量备份 `manifest`：格式版本、来源、时间、实体计数、附件大小/哈希、缺失项、非秘密配置；冻结旧字段映射。真实数据读取/导出另属执行阶段，不在本轮发生。
- Vitest/React Testing Library 用于规则与组件，后端 HTTP/SQLite 集成采用隔离临时库；浏览器流程工具在需要时引入。既有 `sql.js` 仍用于外部 Memos 导入，不能因“删其他后端”提前删依赖。

**不包含**：大规模页面重写、改库引擎、删除旧适配器、真实数据升级。

**验收**：干净 checkout 使用锁定依赖可安装；新增检查脚本真实可运行；类型检查独立于 Vite；CI 执行相同命令；现有问题列表能区分 baseline 与新回归；全部夹具来源为合成数据。已有缺陷可分阶段消除，相关业务切换前必须清零，最终 P8 不带阻塞项。

**回退**：回退工程提交即可，不改变用户数据格式。

### P2：后端骨架与可信身份

**范围**：`server/system/`、`server/services/identity/`、薄入口/注册、前端 `system/api` 与身份状态；在兼容路由接入鉴权，保留现有单工作区产品形态。

- 可信主体区分 owner 与 anonymous；公开笔记可匿名读取，私有笔记、画布、设置、写操作与导入导出必须有有效身份。不虚构多用户/管理员注册体系。
- 建立有期限、可撤销的服务端会话；建议同源 HttpOnly/SameSite cookie，生产 HTTPS Secure，写请求检查来源/CSRF，登录限流。不再用 localStorage 原始口令表示会话；无口令开发模式只能显式启用，生产默认拒绝不完整配置。
- `/api/auth-status` 故障时返回“不可确认/可重试”，不能自动已登录；退出清理私有视图/缓存并处理未提交草稿：先持久隔离待提交内容，禁止静默丢弃或展示给游客。
- 在启用真实401/会话失效前，给旧同步桥补最低限度的失败语义：检查HTTP与`success:false`、只清已确认成功的删除墓碑、失败不推进同步时间；401/退出暂停同步并保留现有本地修改和墓碑。通过定向回归后才开启鉴权切换；完整outbox/revision仍留P4实现。
- `GET /api/settings` 分离公开主题与私有配置，屏蔽旧 `s3_config` 秘密；`/api/init` 转为部署迁移能力，过渡 HTTP 接口默认禁用或仅受控运维可用。
- 错误契约统一；数据库工作单元显式注入。先处理原样 HTML 的脚本/事件属性风险，保留可安全表达的格式；不把清理 XSS 等到旧平台删除之后。

**验收**：SEC-01在现有数据API上的子集、SEC-02、SEC-03的内容渲染/配置子集、API-01、ERR-01（见第4节；导入/代理/媒体子集在对应阶段接入后验证）；认证失败、服务断开、会话过期、退出后刷新均不能提升权限；未登录直接HTTP调用也不能绕过。额外注入旧同步上传/删除401/500，操作和墓碑保留、同步时间不前移；兼容客户端经过统一凭据传递，而非永久开放旧路由。

**回退**：仅回到满足授权边界的版本；不能为兼容重新开放未授权数据接口。旧客户端需停止写入或在新入口下受控适配。

### P3：迁移与契约桥接

**范围**：共享契约、版本迁移、`transfer` 协调用例和旧格式 reader；保留旧数据只读来源，先建可恢复快照。

- 读取旧 Express SQLite、D1 导出中的不同表形态、旧 JSON、浏览器 localStorage/IndexedDB、Electron 原 origin 的存储；同一 memo 的普通/置顶副本按 ID 归一，保存来源与冲突报告。
- 含 `user_id` 的历史源先明确归属映射；多来源相同 ID 冲突不得静默合并。原 ID、时间、公开标记、反链、附件及未知可保留字段都有明确处理；未知/损坏项进入报告。
- 备份包含资产实体；仅对象 URL 不代表离线完整备份。读取外部资产失败要列出未迁项；不得将“只有引用”报告成资产已导入。
- 迁移支持 dry-run、版本检查、幂等 batch ID 与失败恢复；文件先暂存/校验，数据库短事务提交映射；失败不标成功、不清源。大包按有记录的批次执行，失败时不展示成完整迁移。
- 先提供旧格式到规范中间模型的桥接；P4–P6 按域切换，未切换域仍从原路径读取。P3先将SettingsContext的混合同步拆成可独立停用的域操作；P4切memos前必须禁用旧memo upsert/delete/downmerge，以及旧settings的pinnedMemos读写和相应事件回流。未迁设置只允许尚未迁移字段的限定写入，不能继续整包默认值覆盖；按域只有一个写入者。桥接删除门禁为P7对账完成。
- 旧 Memos SQLite 导入必须使用一致性数据库备份；当前代码接收 WAL 文件不等于能合并 WAL，需实现真实支持或明确拒绝不一致输入。

**验收**：MIG-01、MIG-02先验证源解析/完整中间包/暂存与已实现导入部分；中间包读回后计数、ID、公开性、反链、置顶及实体附件hash一致，未实现目标域明确标为待应用，不能伪报应用恢复。重复批次无重复、断进程可重试；旧同步域开关与字段限定经过契约测试。MIG-03完整应用恢复在P5/P6完成后由P7联合验收；不导出会话、原始口令、AI/S3密钥到普通备份。

**回退**：恢复经过校验的源副本与旧版本。迁移后若已接受新写入，先停止写入并导出增量或做前向恢复，不把旧库直接盖回去。

### P4：笔记纵向闭环与可靠同步

**范围**：`memos` 域、统一实体/标签/反链/置顶、对应 DTO/API、笔记列表/编辑/公开视图和客户端提交队列。先用一个“新建笔记→后端落库→重新加载”切片验证架构，再迁其余操作。

- 一个 memo 一份核心数据；置顶是引用/排序，不再从正文集合搬走或存完整副本。列表/画布操作最终调用同一用例。
- 激活新memos路径前，验证P3的域隔离：编辑外观/画布/音乐、旧app事件、定时同步均不能触发旧笔记写入或回填pinnedMemos。旧域跨笔记操作暂接新用例，不能保留第二条笔记写通路。
- 后端数据是权威来源；浏览器缓存与编辑草稿独立，不再用整包 localStorage 上行覆盖数据库。使用服务端 revision/条件更新，旧客户端时钟不决定冲突胜负。
- 每个变更持久化 operationId/baseRevision，确认成功后才移除 outbox；删除产生服务端 tombstone 或同等删除记录。列表未返回某条数据不能视为删除，分页不能触发误删。
- 多实体操作（笔记+标签+反链+置顶/删除记录）在一个工作单元提交；跨域清理调用公开用例，不直接改对方表。请求重试不重复创建，不重复清理资产。
- 匿名缓存与 owner 缓存分离；公开数据同 ID 内容更新必须可见，所有相关页面只拿到当前主体允许的数据。
- 保留离线编辑已有加载数据与可恢复草稿的能力；未载入数据不能假称离线可读，未实现应用离线启动时不宣称 PWA。

**验收**：MEM-01、MEM-02、SYNC-01、SYNC-02、SEC-01；两个客户端旧版本更新得到冲突而非覆盖；断网保存、关闭/刷新、重连后可恢复；DELETE 失败不清待处理项；删除成功旧客户端不复活；置顶独有笔记正常出现在持久库与导出中。

**回退**：以域为切换单位；仅回到兼容当前 schema/revision 的客户端，保留待提交队列；不启用原来的全量同步器与新同步器同时写。

### P5：工作区与辅助功能归位

**范围**：preferences、canvas、review、music 元数据；拆分 `Index.jsx`、`SettingsContext.jsx`、`SettingsCard.jsx`、`CanvasMode.jsx` 等业务职责，保持现有主题和工作流。

- 外观配置、画布图形/笔记位置、回顾状态、曲库元数据各有归属与版本；不继续把全部业务结构塞在 `user_settings` JSON。
- 页面入口展示列表/编辑/画布/设置/回顾/音乐区域；纯转换抽到 functions，协调放 hooks，领域状态集中。全局 store 只保存跨区域核心数据，派生统计/筛选不重复持久化。
- 回顾日期按明确的本地日规则计算；画布缩放、拖拽、绘制、删除和历史行为建立特征样本。设备音量、播放进度、侧栏开合等保留设备侧，不自动跨设备覆盖。
- 主题/头像/背景等私有与可公开字段分别定义；音乐实体只存媒体引用，播放副作用在播放器边界。媒体上传保持过渡适配，待 P6 完整接入后移除旧路径。
- 明确曲库播放器的唯一生命周期：当前audio位于MiniMusicPlayer，进入画布会卸载它，全屏界面靠music事件控制。先测定切换行为，再将播放控制集中，确保画布/全屏/迷你切换、循环播放、歌词与弹幕联动不出现重复播放器或意外进度丢失。

**验收**：UI-01、DATA-01、MUSIC-01A；新浏览器恢复画布/曲库元数据/回顾/设置；设备播放状态互不污染；播放以合成可读媒体验证，Range与共享资产清理在P6验收。搜索、标签、热力图、反链、分享、快捷键及移动布局回归；空/错/加载/提交状态覆盖；不为拆文件改变按钮和视觉。

**回退**：每域 schema/字段保持兼容窗口；保存原快照与新增版本号，避免以默认值覆盖尚未迁移的数据。

### P6：附件与外部集成归位

**范围**：media 域及文件卷，AI/音乐搜索/背景/一言等集成，前端上传与播放适配；不增加独立后端进程。

- 默认存 `/data/uploads`（本地开发等价目录）与 SQLite 元数据，文件以稳定 mediaId 引用，记录大小/MIME/hash/状态。上传可校验、取消、失败清理，下载支持音频 Range 与正确 Content-Type。
- 将 Base64、IndexedDB `musicFiles`（含背景/录音）、旧 S3/R2/MinIO URL/对象逐项归一；临时 blob URL 不能当作迁移实体；第三方播放流 URL 与用户拥有的上传文件区别对待。
- 删除提交后清理无引用资产；共享封面/录音不误删，删除失败可重试。公开文件权限随引用公开策略明确，不能靠“知道 URL”读取私有附件。
- AI 改为前端→自有后端→配置服务，后端持密钥，保留流式输出、取消与模型配置；请求只带授权且必要的笔记上下文。对话历史当前仅内存，持久化不是默认新增需求。
- 音乐搜索/解析、背景收藏、一言等统一适配错误与超时；背景代理补齐 Express 能力，同时限制 URL/重定向/目标网络、响应类型与大小，防止变成任意内网请求入口。
- 首版不重建客户端多对象存储配置；如业务确需服务器侧通用 S3 可选适配，在此阶段单独记录决策，不能拖延默认本地文件卷闭环。

**验收**：MEDIA-01、MEDIA-02、MUSIC-01B、EXT-01、SEC-03；新 origin 能恢复旧 IDB 录音/背景；音乐上传无需 Cloudflare 账号，Range/共享资产删除正确；重复上传/断传/413/磁盘不足保留明确失败状态；公开/私有资源授权正确；AI 流/取消和外部失败有可见错误且不影响笔记编辑。P5/P6合并后执行MIG-03完整应用恢复，作为P7入口。

**回退**：旧实体不删除直到新文件 hash 和引用验证通过；新文件 orphan 清理与数据库恢复分开，保留可重新关联清单。

### P7：数据切换与旧平台退役

**范围**：按 [架构文档退役矩阵](architecture.md#8-退役与保留矩阵) 逐项处理，禁止“搜索到 D1 就删”。

1. 对旧部署/桌面/浏览器来源做完整备份与隔离恢复演练；记录未取回资产/冲突并解决。
2. 进入受控切换窗口，停止旧客户端写入，处理未提交项，迁移最终增量并对账；保留只读备份与回退版本。
3. 验证新 API/存储是唯一写入来源；把 D1 命名客户端替换为按业务用例的 API 调用，移除 fallback/mock/平台判定。
4. 删除 `functions/api/`、`worker.js`、`_worker.js`、Wrangler 配置模板、D1 专属脚本；先把仍被 Docker 引用的 schema 迁为自有迁移来源，再清理引用。
5. 删除 Electron main/preload、桌面组件/标记/config、构建脚本/依赖及文档。旧安装程序和原 profile 数据归档在源码外，不能随代码删除清空用户存储。
6. 清理 Supabase 文档/env 残留、旧提供商选择、Cloudflare/D1/Electron 操作提示；保留历史迁移 reader/样本时写明只读用途与无运行时依赖。
7. 同步 README、AGENTS、CLAUDE、环境示例、包元数据、Docker 和持续集成，避免后续 agent 被旧默认架构误导。

**验收**：RETIRE-01、MIG-03、DEPLOY-01 冒烟；源码 import/调用图/依赖中无退役运行路径；允许的历史术语仅在迁移 reader、测试夹具、历史说明中，并有清单；无功能入口仍需桌面 IPC/Cloudflare 账号；仅置顶笔记、画布、回顾、曲库、文件实体全部对账。

**回退**：保留旧版本+完整数据快照；切换后新增数据必须先导出并转换/前向修复，禁止盲目回滚到旧 schema。回退仍须保持 P2 权限边界。

### P8：开发与 Docker 交付验收

**范围**：统一 Node 主版本、可复现安装/构建、前端与后端产物、环境配置、Compose 和运维指南；不新增 Kubernetes/分布式部署。

- 开发命令一次启动前后端，API 代理一致；构建后 Node 可直接同源服务，Docker 执行同一业务应用。
- 镜像不包含用户数据、秘密、旧平台代码或开发工具；非 root 运行，健康/就绪检查明确，进程正确停止。补齐 `.dockerignore` 对本地数据目录的排除，验证镜像层不带本地数据库。
- 数据库、WAL 与 uploads 使用明确持久卷；SQLite 采用受支持的一致性备份方式，不在活跃写入时单拷贝 `.db`；升级迁移有版本锁/失败停止，不在健康检查或匿名请求里迁移。
- 文档说明首启、口令/会话配置、端口、数据目录、备份恢复、升级回退与故障排查；模板无可直接用于生产的默认秘密。

**验收**：DEPLOY-01、DEPLOY-02；本地与 Docker 运行同一端点和浏览器主流程；容器重建、宿主重启、迁移失败后数据可恢复；干净环境从文档独立启动；P1–P7 相关测试及最终 typecheck/lint/build 通过，无未说明的跳过/失效门禁。

## 4. 验收用例索引

以下是待实施的行为验收，不是已经运行的测试。准备合成数据；实际命令在P1建立后记录到验收报告。各阶段只对已实现的子场景验收并记录覆盖范围，尚未实现的接口不能把404算作授权通过或功能失败；P7/P8执行完整目标矩阵。

| ID | 输入/场景 | 必须观察到的结果 |
|---|---|---|
| SEC-01 | 匿名直接 HTTP 请求私有笔记、设置、写入/导入/文件；请求 public 视图 | 私有路径 401/403，公开响应只含公开 DTO；无需依赖隐藏按钮 |
| SEC-02 | 登录错误/过期、auth-status 500、退出后刷新与切游客 | 不自动已认证；cookie/会话失效；不泄漏私有缓存，未提交草稿不静默丢失 |
| SEC-03 | 旧 raw HTML、恶意 URL/重定向、上传伪 MIME、读取配置与备份 | 无脚本执行/内网任意代理/路径穿越；秘密不出现在普通 DTO/备份/日志 |
| API-01 | 合法/非法字段、JSON、时间、布尔、枚举；旧接口映射 | 合法结果与 schema 一致；非法请求 400；无反射路由冲突，兼容窗口有明确终点 |
| ERR-01 | 数据库错误、约束冲突、外部超时、请求体超限 | 400/401/403/404/409/413/5xx 分类明确、可关联诊断，用户文案不含 SQL/堆栈/秘密 |
| MEM-01 | 普通与置顶创建/编辑/删除，标签/双链/公开切换，刷新与第二客户端 | 唯一实体、引用正确、公开性一致；图形/列表入口同一业务结果 |
| MEM-02 | 写笔记+标签/引用的中间步骤失败 | 同一事务全部回滚；不会留下半条业务记录 |
| SYNC-01 | 离线变更→重载→重连；上传/DELETE 单项 401/500 | 待提交记录保留，恢复后幂等；未确认删除不清墓碑，无“假成功” |
| SYNC-02 | 两客户端同一 baseRevision 更新；旧缓存对已删数据重试 | 409/明确冲突保留两方内容；删除不复活，不靠客户端时钟覆盖 |
| MIG-01 | 各旧格式、重复批次、同 ID 不同来源、损坏/缺字段数据 | 预览数量与冲突；幂等结果；拒绝/隔离损坏项且旧数据不变 |
| MIG-02 | 迁移/恢复中断、磁盘不足、事务失败、缺附件 | 可重试或回退；未完成批次不冒充成功；有未迁项报告 |
| MIG-03 | 完整包恢复到空实例/新 origin | 实体 ID/计数/字段、置顶/画布/回顾/曲库、文件大小/hash/引用匹配 |
| DATA-01 | 跨浏览器加载业务配置与画布/回顾；本机偏好变化 | 业务配置恢复，音量/进度等设备状态不错误串写，日期边界符合约定 |
| UI-01 | 列表/画布、搜索/标签/热力图、双链/分享、快捷键、窄屏；加载/空/错 | 功能与视觉基线保留，键盘可用；权限/错误状态一致，快捷键不能绕过授权 |
| MUSIC-01A | 曲库元数据导入、切歌/循环、封面/歌词/弹幕、音量/进度/刷新、画布/全屏/迷你切换；使用合成可读媒体 | 播放与元数据恢复符合基线，唯一播放器生命周期一致，设备偏好不串写；P5验收 |
| MUSIC-01B | 自有媒体上传/Range播放、删除共享资产曲目、文件清理失败 | Range可用，不误删其他引用，不因单文件失败丢元数据；P6验收，P7联合验证 |
| MEDIA-01 | Base64/IDB/远端对象迁移、大音频/背景、跨 origin 恢复 | 实体可读、hash/类型正确、旧引用可追溯；没有把 blob URL 当永久内容 |

## 5. 阶段报告与停止条件

每阶段交付记录改动文件/领域、契约与数据变化、实际检查命令及结果、兼容层剩余项、风险、恢复步骤和下一阶段入口条件。源码检查、自动测试、本地浏览器、Docker、真实迁移结果分别列出。

出现未解决数据计数/hash 差异、未知归属冲突、丢失待提交记录、授权绕过、无法恢复的 schema 变化，停止相应切换或删除步骤；保留只读来源，修复或明确处置后继续。不得以“构建成功”“页面能开”或“没有报错”替代阶段验收。

首次执行从 P1 开始；不在本次文档任务中启动实施，也不提交、推送或部署。
