# Meow 全新版本分阶段重写计划

状态：**P0–P8 已实施，本机验收完成。** 各阶段验证证据、环境边界和未实测项见 [implementation-status.md](implementation-status.md)。更新日期：2026-10-24。

架构、功能与源码依据见 [architecture.md](architecture.md)，执行规范见 [AGENTS.md](../AGENTS.md)。本文的阶段与用例为完整交付要求，完成情况以实际实现和运行证据为准，不把静态审计当作运行验收。

## 1. 已确定的范围与实施原则

用户已明确：**这是一次完全彻底的更新重写，不考虑旧版本兼容。** 以当前 `server/` 的 Node/Express/SQLite 技术基础建设唯一业务后端，前后端采用严格 TypeScript；删除 Cloudflare Pages / Workers / D1 等替代后端支持及 Supabase 残留；同时退役 Electron 打包和桌面专属代码。交付方式为本地正常开发/Node 运行与 Docker。

新版本从**新实例、新 schema、新配置、新 API 契约和新的浏览器存储命名空间**开始。不提供旧 Meow API、数据库、配置键、localStorage/IndexedDB 或备份格式的兼容层；旧数据搬迁、桌面 profile 导出、迁移桥、双轨业务运行、最终增量对账、回退到旧 Meow 均不属于实施任务或验收门禁。旧代码仅用于识别产品需求与已知缺陷，不能约束新结构和协议。

保留浏览器中的笔记、标签/搜索/统计、反链、公开访问、画布、回顾、录音/附件、音乐、AI、分享、外观设置及导入导出能力。用户已明确：保留原有界面和视觉效果，只升级实现。布局、主题、字体、组件、动画、响应式与交互须对照旧版验收；不要求保留旧目录、存储实现或错误行为。**外部 Memos 数据导入是保留的产品能力**，按新版本明确支持的输入格式重新设计，不是对旧 Meow 的兼容。首版附件默认由自有后端文件卷管理；AI/音乐等第三方服务作为受控集成保留，凭据留在后端，不重建客户端 S3/R2 平台选择器。

完全重写仍按可验证的纵向用例分阶段交付，不先堆空目录再集中验收。保留新版本自身的事务、并发控制、离线队列、备份恢复及发布后的版本化 schema 演进。开发中各模块可以先后替换，但新应用不调用旧后端、不读写旧存储、不建立双写链路；未完成能力明确列为未完成。

不做兼容并不授权删除或覆盖真实旧数据库、浏览器存储、Electron profile、远端桶和云资源。新版本使用独立数据路径和命名空间，遇到旧版或未知 schema 应拒绝误用并给出说明；不自动清空、导入、升级或覆盖。移除仓库支持代码与处置已部署资源是不同操作。

## 3. 各阶段执行清单

### P1：工程与需求验收基线

**范围**：`package.json`、锁文件/忽略规则、Node 配置、lint/TypeScript/test 配置、质量 CI、隔离测试设施和需求样本。先记录原有检查现状，再为新实现建立可执行门禁；不因旧代码问题把无关修补加入重写范围。

- 新写前后端及共享契约使用严格 TypeScript，独立类型检查，不把 Vite 构建成功当类型安全。存续旧源码与新实现的检查边界明确列出；每次新增/替换模块必须进入门禁，最终产物不能带未纳入检查的旧业务代码。
- 合成目标场景覆盖普通/置顶笔记、公开/私有、标签/反链、画布、回顾、曲库、录音、草稿、待提交操作、并发冲突、空态、损坏输入和失败状态。数据格式围绕新模型，不建设旧 Meow 格式 reader 或旧库夹具矩阵。
- 把现有可观察能力转成新产品验收场景；明确搜索无结果、业务日期/时区、删除引用、公开投影和播放器模式切换等规则。已知安全/同步缺陷不写成必须复现的正确行为。
- Vitest/React Testing Library 用于纯规则与组件；后端 HTTP/SQLite 集成使用临时库；涉及浏览器持久化的测试使用隔离 origin/profile。应用创建必须能注入临时依赖，不因 import 自动连接真实数据库或监听端口。
- 定义新版本备份的覆盖需求，包括所有业务实体、附件实体、引用和非秘密配置；P7 再实现与验收完整包。外部 Memos 导入列入需求，解析器及 `sql.js` 是否复用按新输入合同决定，不按平台关键词删除。

**验收**：QUALITY-01；干净 checkout 使用锁定依赖可安装，lint/typecheck/test/build 命令真实可运行，CI 与本地一致；旧检查问题与新实现问题分开记录。此阶段通过代表工程门禁建立，不代表业务重写完成。

**失败处置**：修复或撤回本阶段工程改动，不连接、转换或重置用户数据。

### P2：新应用基础与可信身份

**范围**：新 `server/main.ts` / `app.ts`、system/identity、域路由注册、前端统一 API 传输和会话状态；只建设单工作区 owner/anonymous，不新增多用户注册体系。

- Node/Express/SQLite 保留为技术基础，旧路由和启动副作用不作为复用约束。主入口管理启动、schema 调度、监听与关闭；应用工厂接收显式依赖；system 不导入具体业务规则。
- 使用新配置合同及独立数据根目录。空目录初始化为新实例；配置指向旧数据库、未知 schema 或非本应用数据时停止启动，不能尝试自动建表覆盖。新文件卷路径与数据库一起声明。
- 建立到期/可撤销会话，服务端持久化会话 token 哈希；同源 HttpOnly/SameSite cookie，生产 HTTPS Secure，写请求防 CSRF、登录限流。客户端不保存原始口令；未配置身份不能默认获得 owner。显式本地开发模式如确有需要，须有独立配置和可测边界。
- 会话查询失败进入不可确认/可重试状态，不自动登录；退出停止私有订阅并清理可展示缓存。未提交草稿采用仅重新认证后可恢复的隔离策略，不向游客暴露、不静默丢弃；P4 将策略接入持久队列。
- 路由显式声明 public/owner，身份在边界解析为可信主体；统一输入验证、错误 DTO、requestId 和脱敏日志。SQL 仅进入表模块；同一用例的数据库工作单元由框架建立，表方法不提交事务。

**验收**：SEC-01/SEC-02/API-01/ERR-01 的身份和已实现路由子集，FRESH-01 的服务端路径子集；有效/失效会话、错误口令、网络错误、退出后刷新和直接 HTTP 调用均验证。P2 不以尚不存在的笔记/文件路由返回 404 来冒充授权通过。

**失败处置**：新实例拒绝就绪并保留诊断，修复新版本身份边界；不回接旧未授权 API。

### P3：新 schema、契约与存储基础

**范围**：新领域模型与表约束、共享 schema/DTO/路由注册表、版本化初始化、新缓存/草稿命名空间，以及“新建笔记→后端落库→刷新列表”最小完整链路。不预建全部领域空壳。

- 按领域唯一归属设计新模型；领域对象、传输 DTO、数据库行显式分离。规范字符串 ID、ISO8601 UTC 时间、布尔/数组/对象以及业务日期；不接受旧字段别名或字符串化 JSON 兼容输入。
- 新库从初始版本创建，迁移历史属于这次重写后的 schema 序列；初始化可重复检查，失败停止，禁止降级误写。不开发从原 `memos/user_settings`、D1 schema 到新模型的转换脚本。
- `shared/contracts/<domain>/` 作为唯一请求/响应与路由事实来源；一个公开用例对应一个 `<Action>APIMessage.plan` 与前端 `<Action>API`。注册冲突检测、运行时校验和统一错误在真实 Create/List 链路验证，不生成无消费者 DTO。
- 浏览器新命名空间按实例/主体/格式版本隔离缓存、草稿和设备偏好；不读取旧 `memos/pinnedMemos` 等键或 `MeowNocodeLargeFileStorage`，也不删除它们。实例标识变化、退出和 schema 不支持均有可观测状态。
- 建立服务端权威实体与分页读取规则；客户端草稿不是另一份可反向覆盖服务端的全量真相。为 P4 定义 operationId/baseRevision、服务端 revision 和确认语义，完整队列重试在 P4 实现。

**验收**：SCHEMA-01、FRESH-01、API-01；从隔离空目录/新浏览器创建并刷新笔记可见，非法输入拒绝，行字段不直接泄漏到 API。预放合成旧版库/浏览器键后运行新应用，新应用不继承旧内容或修改旧字节；明确指定旧/未知库时拒绝启动。新 schema 初始化重跑不丢已创建数据，失败不留下“已升级”的假记录。

**失败处置**：保留失败的新实例和版本诊断；可销毁并重建明确为合成测试用途的临时库，不能用此方法处理真实数据。新版本发布后的升级失败须使用本版本恢复流程或前向修复。

### P4：完整笔记与可靠同步

**范围**：memos/tags/links/pins、列表与编辑区域、公开访问、共享笔记操作和持久 outbox；在 P3 链路上补全真实业务能力。

- 一个 memo 一份核心数据；置顶仅引用/顺序，标签/双链规则归笔记域。创建/编辑/公开切换/删除/预览使用统一用例，画布在 P5 调用同一入口。
- 服务端生成 revision/time，写入携带 operationId/baseRevision；条件更新拒绝过期版本，重试幂等。冲突保留本地草稿和最新服务端内容，不能静默按客户端时间最后写赢。
- 先持久化变更意图再发送；确认成功后才能移除 outbox。删除保留服务端删除记录或等效机制，失败不丢意图，分页缺项不能推断删除；同一新版本的离线客户端不得复活已删除内容。
- 笔记、标签、反链、置顶/删除记录的关联修改同一工作单元原子提交。跨域完整操作由 workspace 编排调用公开用例，不跨域写表；相关域在 P5/P6 实现后补齐联合测试。
- 匿名只接收公开投影；列表、搜索、标签统计、预览、热力图、AI 上下文等不能读到私有缓存。安全内容渲染覆盖 Markdown/HTML 的脚本和危险属性，保留允许的表达形式。
- 覆盖中文输入、快捷保存、失败重试、离线编辑已载入数据和刷新后草稿恢复；未载入数据不假称可离线读取，不将此默认扩展为完整 PWA。

**验收**：MEM-01、MEM-02、SYNC-01、SYNC-02、SEC-01/SEC-02、SEC-03 的内容渲染子集；双客户端并发得到明确冲突，断网保存/重载/重连最终幂等，DELETE 失败保留队列，确认删除后离线重试不复活。匿名公开内容同 ID 更新能够正常刷新。

**失败处置**：停止有问题的提交/同步操作并保留草稿与队列，修复新实现；不启用旧整包 localStorage 同步作为降级路径。

### P5：工作区与辅助功能重写

**范围**：preferences、canvas、review、music 元数据，首页各业务区域及 hooks、设备偏好和播放器；新领域独立建模，不沿用巨型 `user_settings`。

- 外观配置、画布图形/笔记位置、回顾状态、曲库元数据各有拥有者与版本；画布位置只有一个来源，memo 引用使用稳定 ID，删笔记后的画布/回顾引用由完整用例协调。
- 入口直接展示主要业务区域；纯转换放 functions，协调放 hooks，共享核心状态按域管理。筛选/统计/热力图在读取时派生，不使用 Effect 保存副本。
- 画布新建/编辑/拖拽/平移/缩放、各绘图工具、层级/删除和最后修改持久化逐项验收；回顾 PASS/FAIL、日期/随机池、翻面/快捷键采用明确业务日与时区规则。
- 主题/头像/背景的公开字段与私有偏好区分；音量/播放进度/侧栏状态等设备态不跨设备覆盖。记录刷新恢复规则，不能从旧键隐式继承设置。
- 曲库实体只持稳定媒体引用；集中播放器生命周期，画布/全屏/迷你切换只使用一个播放实例，循环、歌词、弹幕、进度和音量一致。P5 以合成可读媒体证明交互，P6 接入真实媒体能力，不引入旧 S3 上传适配。

**验收**：UI-01、DATA-01、MUSIC-01A，并补 MEM-01 的列表/画布联合删除；新浏览器从后端恢复业务配置、画布、回顾和曲库；设备状态不串写。搜索/标签/热力图/双链/分享、快捷键、窄屏、首次引导及加载/空/错/提交状态满足需求；DOM 和文件拆分不作为验收指标。

**失败处置**：保留新版本业务数据和已确认状态，失败写入不以默认值覆盖已有记录；修复域内规则后重试。真实附件子场景未接入时明确等待 P6，不写成整个功能已完成。

### P6：媒体与外部集成重写

**范围**：media 域、文件卷、录音/上传/播放，AI、音乐搜索/解析、背景和一言等集成；仍为同一后端部署。

- 新上传默认存自有持久文件卷与 SQLite 元数据，记录 mediaId、大小、MIME、hash、引用和状态。文件先暂存与校验，再在短事务关联；网络/文件长操作不占数据库事务；孤立文件清理可重试。
- 录音暂停/继续/取消、图像/背景/音乐上传、下载和音频 Range 通过真实文件闭环。离线待上传实体明确持久化位置和失效状态，不能只保存生命周期短暂的 blob URL。
- 删除只清无引用资产，共享封面/录音/画布图片不得误删；数据库提交后清理失败独立重试。私有下载、公开引用传播、缓存和公开性撤销有一致授权策略。
- AI 经自有后端调用配置服务，密钥仅后端，保留流式、取消、模型配置和必要授权上下文。聊天历史持久化不属于默认新增需求。
- 音乐搜索/解析、背景收藏/一言通过受控适配器；对外请求限制目标网络、重定向、大小、类型、超时和取消。外部流 URL 与用户上传文件分别建模，不能将暂时可读外链当作已备份实体。
- 不导入旧 IDB/Base64/S3/R2/MinIO 资产，不访问旧对象桶；若用户后续另行要求服务器侧通用 S3，再独立设计，不阻碍本地文件卷首版闭环。

**验收**：MEDIA-01、MEDIA-02、MUSIC-01B、EXT-01、SEC-03 的媒体/代理/凭据子集；无需 Cloudflare 账号即可上传和 Range 播放。权限拒绝、重复提交、断传、413、磁盘不足和清理失败均可观测/可恢复；AI 取消和第三方失败不影响笔记编辑。完成后与 P5 联合执行媒体引用与播放器测试。

**失败处置**：保持已提交引用一致，失败暂存项可清理或重试，不能将提交后的文件清理失败假报为数据库已回滚；文件与数据库恢复在 P7 联合验证。

### P7：新版数据保障与旧实现退役

**范围**：transfer 用例、新版完整备份恢复、外部 Memos 导入、全域联合测试及 [旧实现退役矩阵](architecture.md#8-退役与保留矩阵)。这一阶段不进行旧 Meow 数据切换。

- 设计新备份格式 `manifest + entities + assets`：格式/schema 版本、实例来源、导出时间、实体计数、附件大小/hash、引用和缺失项。会话、口令、AI 密钥不进入普通备份；运维秘密独立配置。
- 从新应用创建覆盖所有域的数据与文件，产生一致性快照并在隔离空实例/新 origin 恢复。活跃 SQLite WAL 使用受支持的一致性备份机制；文件快照有版本/引用清单，不能仅复制 `.db` 或导出 URL 就声称完整。
- 新版恢复先验证版本/完整性/引用，再暂存文件并按声明的原子范围提交；大包分批必须有可恢复状态与可见进度。重复 batch ID 幂等，中断/磁盘不足/缺文件不冒充成功；备份包含业务数据，设备偏好是否可选导出需在 manifest 明确。
- 外部 Memos 导入只支持明确列出的完整 SQLite 一致性快照及可选资产输入；先探测表/字段、预览数量与冲突，再调用本域用例导入。源 ID 与本应用 ID 显式映射，重复来源批次不重复；公开性/置顶/标签/时间转换规则有测试。不接受单独 WAL/SHM 作为完整输入，不宣称支持未知 Memos 版本或未提供的附件；缺失资产列明，源文件只读。
- 新版完整能力验证后清除旧 API 客户端、mock/fallback、旧 Context 同步器和失去消费者的旧业务实现；无旧协议适配、旧数据 reader 或双写桥保留。按模块完成替换时可提前删除对应旧源码，P7 对最终剩余项做闭环，不要求维护旧应用可运行。
- 删除 `functions/api/`、Workers、Wrangler、D1 专用 SQL/配置/依赖，Docker 仅使用新 schema；清理 Supabase 残留。删除 Electron main/preload、桌面组件/标记、脚本/依赖和活跃文档；共享资源按引用核验，`concurrently` 等仍服务开发的依赖不机械删除。
- 同步 README、AGENTS、CLAUDE、环境示例和包元数据。退役仅影响仓库实现，不删除真实旧库、安装/profile、云账号/桶/对象或现有服务；新应用也不自动清理旧浏览器键。

**验收**：BACKUP-01、BACKUP-02、IMPORT-01、RETIRE-01，复核 FRESH-01 与完整 SEC-01/SEC-03；全量新版包恢复后 ID/字段/计数、置顶/画布/回顾/曲库、附件 hash/引用一致。代码/依赖/构建产物无旧平台或兼容运行路径，保留历史术语仅在明确标注的说明材料中。外部导入不以“能打开 SQLite”代替全部声明字段和失败场景验收。

**失败处置**：停止新版本导入/恢复并保留完整性报告、源包和暂存状态，按已声明的原子边界恢复/重试或前向修复；不向旧 Meow schema 转换，也不覆盖真实旧实例。若旧实现残留仍被新应用调用，应补齐新能力或移除依赖后重验。

### P8：本地与 Docker 交付验收

**范围**：统一 Node 主版本、安装/构建与产物目录、环境配置、Compose、持久卷和运维指南，不新增分布式部署。

- 开发命令启动 Vite 与新 Express 应用，代理一致；构建后 Node 同源服务前端与 API，Docker 运行同一套业务应用和新 schema。
- 镜像不带用户数据、秘密、旧平台或开发工具；非 root 运行，健康/就绪检查明确，信号关闭正确。`.dockerignore` 排除运行数据目录，检查镜像层无本地数据库/附件。
- DB/WAL 与 uploads 在声明的持久卷中；新版本自身的 schema 演进有版本锁、已应用记录与失败停止，不能由健康检查或匿名请求触发。验证初始 schema 到后续合成版本的演进；不把它扩展成旧 Meow 兼容。
- 文档说明从空实例首启、会话配置、端口、目录、新备份恢复、后续升级和失败修复；模板不带生产默认秘密。说明不支持旧 Meow 库/备份直接使用，但不附带自动重置/清旧数据脚本。

**验收**：DEPLOY-01、DEPLOY-02、SCHEMA-01；本地与 Docker 执行同一 API 和浏览器矩阵。容器重建/进程重启保持新版 DB+文件数据；升级失败不会丢失既有新版数据，备份可恢复。干净环境按指南独立启动，P1–P7 相关检查及最终 typecheck/lint/test/build 全部通过，无未说明跳过或阻塞缺陷。

## 5. 阶段报告与停止条件

每阶段记录改动文件/领域、新契约与数据定义、实际检查命令和结果、未完成能力、已知风险、失败恢复步骤与下阶段入口。源码检查、自动测试、本地浏览器、Docker 和真实外部服务验证分别报告。没有实施的用例保持待验收，不能以旧实现仍可用作为新版本完成证据。

出现授权绕过、丢失待提交记录、事务不原子、新版备份计数/hash 不一致、无法恢复的 schema 变化，暂停相关发布步骤并修复。发现新代码读取/覆盖旧实例，停止该操作并修正隔离边界。此类门禁保障新版本正确性，不重新引入旧版兼容和数据迁移任务。

实施从 P1 开始并持续完成全部阶段。提交、推送和外部部署按用户授权范围执行；本地实现与隔离验证属于已授权的升级任务。
